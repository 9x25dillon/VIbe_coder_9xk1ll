## What was built

[S004](2026-09-03-S004-interactive.md) recorded T7 W8 as **partial** rather than
met: the waypoint asks for the three axes to assemble "as tests report", and
what shipped animated a finished result over 0.9 s. It looked like the intended
thing and was not it. This session built the real one.

The obstacle was the wire protocol. `_harness.py` wrote a single JSON object at
the very end, so there was nothing to stream and no amount of front-end work
could invent it. The reply is now **newline-delimited events**: zero or more
`{"event": "progress"}` lines as each test lands, then exactly one
`{"event": "result"}` line carrying the whole run. A parent that does not care
reads to the end and takes the last line; one that does reacts as they arrive.

`run_code` gained `on_progress`. Without it the old `subprocess.run` path is
used unchanged — `communicate` waits for the child, which is correct when
nobody is watching and avoids paying for a reader loop that would observe
nothing. With it, a `select` loop over the raw descriptor reads lines as they
appear and enforces the wall clock itself, because `communicate(timeout=)`
would block until the child finished and there would be nothing left to stream.

**Only Accuracy assembles, and that is the honest answer.** It is
passed-over-total and both numbers are known as each test lands. Speed needs
the elapsed total; Functional needs the operation count against the reference;
neither exists until the run is over, so neither is drawn until it is. Filling
all three from a partial result would have looked better and meant less — the
same trade S004 refused when it recorded the waypoint partial in the first
place.

Two smaller items from the same list of open work. The keystroke-latency
assertions now compare a **95th percentile** rather than a worst case (Q27): a
worst-of-N wall-clock measurement tests the machine as much as the code, and
one scheduling hiccup from a parallel Docker run had already failed a build
that proved nothing. The worst case is still reported when the assertion
fails. And the auto-indent bug found while capturing a screenshot — `if x:  #
note` not opening a block — was fixed in `fddf54c`.

## Misconceptions and corrections

### M13 — A protocol migration is done when the tests pass

**Believed:** Converting every reply write to the new event format was
mechanical, and the suite passing meant it was complete.

**Revealed by:** Three test failures after the change, two of which were the
same bug: the `SyntaxError` branch still wrote a bare `json.dump(result,
sys.stdout)` with no event wrapper and no newline. It had been missed because
the edit targeted surrounding context that branch did not share.

**Corrected to:** Converted, and then guarded by `TestReplyProtocol`, which
*drives* each terminal path — success, syntax error, missing function,
import-time crash, failing test — and asserts the parent could read what came
back. A grep would have found the one instance; the test finds the next one.

**Cost:** ~10 minutes. The useful part is that the old format still "worked"
for the writer and only failed at the reader, which is the signature of a
half-migrated protocol and the reason the guard is worth more than the fix.

### M14 — A substring in the captured output proves the feature works

**Believed:** Checking the pty capture for `"run "` and `"acc "` confirmed the
live row and the final axes had been drawn.

**Revealed by:** The check reported the live row present when the code that
draws it had not been wired in at all — a `replace()` had silently failed
because the target text had changed in an earlier session. `"run "` matched the
word `running`, which is the *fallback* the same function prints when there is
no live state.

**Corrected to:** Replaying the captured bytes into a grid and asserting on the
reconstructed frame, plus counting cursor-position sequences addressed to the
score row as a direct measure of how many times it was redrawn. 44, where a
non-streaming build would emit two.

**Cost:** ~10 minutes, and it nearly shipped a feature that was not connected.
Two lessons worth separating: a string search over damage-tracked terminal
output is not a frame assertion, because the diff emits partial rows in
fragments; and an edit applied by matching source text needs its match
asserted, which is why the corrected version of that edit begins with an
`assert`.

## Friction

- The streaming path leaked both pipes on the timeout branch, which raises
  before reaching the close. Caught by running the suite under
  `-W error::ResourceWarning` rather than by a test.
- Three provenance routing tests assert the fast path, which a pinned backend
  legitimately overrides. They now skip under a pin, the same way the escape
  suite does — the assertion describes `auto`, and saying so is better than
  making it describe both.

## Decisions

| # | Decision | Alternatives considered | Rationale | Reversible? |
| --- | --- | --- | --- | --- |
| D42 | Newline-delimited events, one `result` line last | A length-prefixed frame; a second pipe for progress | Readable by `readline`, trivially skippable, and the last line stays the whole reply so nothing downstream changes | yes |
| D43 | `on_progress` is optional and the waiting path is kept | Always stream | Nobody watching means nothing to stream, and `subprocess.run` already handles the timeout correctly | yes |
| D44 | Only Accuracy assembles live | Fill all three from partial data | Speed and Functional do not exist until the run ends; drawing them early would look better and mean less | no |
| D45 | Progress is emitted after the untraced pass | After the traced pass, with final numbers | The instrumented pass roughly doubles the wait, and a player watching should not | yes |
| D46 | Events are written to a stdout captured at import | Write to `sys.stdout` at call time | The submission's stdout is redirected away; capturing the real one at import is what stops a submission printing a forged event | no |
| D47 | Latency budgets assert a 95th percentile | Worst of N; a wider worst-case budget | A worst case measures the machine; a wider budget stops measuring anything | yes |
