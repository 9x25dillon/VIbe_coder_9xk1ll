## What was built

`cockpit.py` supplies bounded, column-aware text, shared headers and scrollable
inspectors. The editor exposes objective/help views, optional typing rhythm,
horizontal source scrolling, persistent verdict/failure/advice rows, and score
comparison within the current editor session. Its wide layout starts at 110
columns; the minimum remains 48 by 12.

`levels --browse` selects challenges with arrows and Enter, restores its terminal
before launching, and returns after a challenge. The text map names all levels.
Live boss execution composes the existing machine view with current health and
repairs. The terminal is released before the repair inspector opens. Pipes and
reduced-motion terminals use the transcript. No scoring, provenance, persistence
format, repair costs, or trace format changed.

The preview is an SVG of illustrative states composed by the real renderers,
regenerated with `python3.11 tools/preview_ui.py`.

## Misconceptions and corrections

**M58:** I treated `TerminalSession.resized` as a method after following its
existing use in `vision.play`. It is a consuming boolean property. The first
real PTY browser launch raised `TypeError`, although pure frame tests passed.
The new callers and the existing vision caller now read the property; a
browser-loop regression test and boolean mock properties cover the seam.

## Friction

The system `python3` is 3.14, while the handoff requires 3.11. The first baseline
also ran under restricted isolation, making sandbox backends unavailable and
changing discovered test counts. Re-running with Python 3.11 and normal host
access established the green baseline before implementation.
