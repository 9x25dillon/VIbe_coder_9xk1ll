## What was built

Two items, both of them the *unfinished half* of something a previous session
recorded as done.

### The colon that does not open a block

`fddf54c` taught the auto-indent to look past a trailing comment, so
`if x:  # note` opens a block. That fixed the reported bug and left the general
one: the check still ran on the **physical** line, and a colon is only an
opener at bracket depth zero. Inside brackets it is a dict entry, a slice or an
annotation:

```python
d = {
    'key':      # a value follows, not a block
```

which indented, while the case that should indent —

```python
def f(a,
      b):       # the colon that closes a continued signature
```

— indented from the wrong place, putting the body one level in from `b` rather
than from `def`.

[`editing.py`](../vibecoder/editing.py) now scans a line **once** for both
facts it needs, because they need the same thing to be correct: knowing which
characters are inside a string literal. `scan()` returns the code part and the
net bracket delta; `logical_line()` walks backwards from a row until the
running delta goes positive, which is the line holding a bracket open across
it; `opens_block()` asks whether a trailing colon sits at depth zero. The walk
is bounded at 200 lines so that one Enter keypress does not cost the buffer.

A block body now indents from where the *statement* began. A line that opens no
block keeps its own indentation instead, which is what holds a hand-aligned
continuation where the author put it.

### The latency budget, and the defect it was hiding

[S007](2026-09-03-S007-streaming.md) answered Q27 by switching the keystroke
assertions from a worst case to a 95th percentile, and honestly marked the
claim it could not support: *"the budget no longer fails under load — not
re-observed under load, `UNVERIFIED`."* That was the right call with the
evidence available and it turned out to be treating a symptom.

Measuring CPU time next to wall clock separates two things that had been
sharing one number:

```
worst keystroke, CPU ms, 4000-line buffer

  extra live objects     plain   steady_heap
                   0      6.75          5.00
             420,000     20.70          5.16
           4,200,000    102.66          7.38
```

The work is identical in every row. What changes is how many objects live in
the process — and CPython's collector walks them on every pass, so the pause a
player feels was set by the size of the rest of the game rather than by
anything the editor did. That is a real defect, and it would have grown as the
game did. The percentile did not fix it; it moved it far enough down the
distribution to stop being visible.

`steady_heap()` in [`editor.py`](../vibecoder/editor.py) wraps the run loop in
`gc.freeze()`, which moves everything alive at entry into a permanent
generation that collections skip. It does **not** disable collection — garbage
made while editing is still collected — so the trade is the memory of one
editing session against a bounded keystroke, which is the right way round for a
session that lasts minutes and must never stutter.

The budget is now asserted on **two clocks**, because they answer different
questions:

- **Wall clock, median** — what a player feels. It cannot carry a worst-case
  assertion: a keystroke costing 3 ms of CPU was observed taking 145 ms of wall
  clock because the OS descheduled the process, which says nothing about this
  code.
- **CPU time, worst case, 12.7 ms at 4000 lines** — what this code costs.
  Immune to preemption, so it can assert *every* keystroke rather than most of
  them, which is the only form of "never exceeds, even under load" that is
  actually testable.

## Misconceptions and corrections

### M15 — A timing test that fails under load is a flaky test

**Believed:** Q27 posed a choice between two statistics — percentile or worst
case — and S007 picked the percentile. The failure was noise, and the question
was how to stop noise deciding a build.

**Revealed by:** Timing the same keystroke on both clocks, then adding ballast
objects that the editor never touches. Identical work cost 6.75 ms with a small
heap and 102.66 ms with 4.2 million extra live objects, while the editor's own
CPU cost stayed flat at ~5 ms. The variance was not coming from the scheduler
at all.

**Corrected to:** Two problems were wearing one number. Wall-clock noise is
real, is not this code's fault, and belongs to a median. Underneath it sat a
genuine defect — keystroke latency proportional to the total live object count
of the process — that only a worst case could see, and that the percentile
demoted rather than fixed. A test that fails only under load is sometimes
reporting that the code is load-sensitive.

**Cost:** No rework; the diagnosis *was* the work. Worth recording that the
cheap move was available and defensible — S007 had already relaxed the
assertion and written down that the load claim was unverified, so the suite was
green and the gap was documented. Reading `UNVERIFIED` as a task rather than a
disclosure is what turned it up.

### M16 — Handling comments finished the auto-indent rule

**Believed:** After `fddf54c` the trailing-colon check was correct: it looked
past comments and respected string literals, which was every case anyone had
hit.

**Revealed by:** Taking the specification's wording literally — "a colon at the
end of a **logical** line, not just the raw line" — and probing the cases that
phrase distinguishes. `d = {` / `    'key':` indents; a continued `def`
signature indents from the wrong column.

**Corrected to:** Comment handling and bracket depth are the same problem seen
twice, and both need to know what is inside a string. The physical line is
simply the wrong unit for the question.

**Cost:** ~15 minutes. Cheap because the scanner already existed and needed one
more counter, which is the argument for having written it as a scanner rather
than a `split("#")` in the first place.

## Friction

- `tests/test_editing.py` had `if __name__ == "__main__": unittest.main()` in
  the middle of the file, so running that file directly executed only the
  classes defined above it and silently skipped the rest. Discovery was
  unaffected, which is why it survived. Moved to the end.
- The strict bound passes in a freshly started interpreter whether or not
  `steady_heap` is applied, because a small process has little for the
  collector to walk. Only the ballast test fails without the fix, so that is
  the one carrying the guarantee — a reminder that a passing latency test can
  be measuring an environment rather than a property.
- **Every runtime figure in the living docs was stale**, and by a lot: README
  claimed the suite takes "~4 seconds" against a measured 141 s, and CLAUDE.md
  claimed 14 s pinned (38 s), 45 s under Docker (438 s) and "forty seconds
  unpinned" (two and a half minutes). `tests/test_records.py` pins the *test
  count* to reality and nothing pins the *timings*, so they drifted silently
  while the count stayed honest. All corrected against measurements taken this
  session; whether the timings deserve a guard of their own is left open, since
  they are machine-dependent in a way the count is not.

## Decisions

| # | Decision | Alternatives considered | Rationale | Reversible? |
| --- | --- | --- | --- | --- |
| D47 | The keystroke budget is asserted on two clocks | Wall-clock percentile alone (S007); wall-clock worst case alone | They answer different questions: felt latency versus what this code costs. Only CPU time can assert *every* keystroke without measuring the scheduler | yes |
| D48 | The editor freezes the heap for the life of the session | Leave it; disable GC entirely; reduce per-keystroke allocation | Allocation was already low at 21 containers per keystroke; the cost was traversal, not churn. Freezing bounds the pause without disabling collection | yes |
| D49 | The backward walk for a logical line is bounded at 200 lines | Unbounded walk; parse the buffer | Enter must not cost the buffer. A statement spanning more than 200 physical lines is pathological, and the failure mode is one wrong indent | yes |
| D50 | A body indents from the logical line's start; other lines keep their own indent | Always carry the current line's indent | The body of a continued signature belongs one level in from `def`, but a hand-aligned continuation belongs where the author put it | yes |
| D51 | One scanner returns both the code part and the bracket delta | A second function for brackets | Both need to know what is inside a string literal; two scanners means two chances to disagree about it | yes |
