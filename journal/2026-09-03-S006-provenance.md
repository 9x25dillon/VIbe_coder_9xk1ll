## What was built

The mechanism W3 asks for already existed: `run_code(untrusted=True)` forced an
isolating backend in W1 and W2 hardened what that backend does. What was
missing is the part that matters more, which is that **the flag defaulted to
safe-for-us rather than safe-for-the-player**.

A boolean defaulting to `False` means the one argument a future call site can
forget is the one that decides whether a stranger's Python runs on somebody's
machine — and forgetting is silent, because the fast path works perfectly right
up until the day it matters. So `untrusted: bool = False` is now
`source: Source`, with **no default**. Forgetting is a `TypeError` at the call
site rather than a fast path nobody notices.

[`Source`](../vibecoder/models.py) is an enum rather than a boolean because
"untrusted" is a conclusion and the fact underneath it is worth keeping. A run
that must be isolated should say *why*: `PLAYER` is what the person at this
keyboard typed, `BUNDLED` shipped with the game, `THIRD_PARTY` arrived over a
wire. `requires_isolation` is the only place the policy is written down, so if
isolation ever becomes cheap enough to apply to everything, one property moves
and nothing else does. It lives in `models.py`, which depends on nothing —
that is the rule the module map rests on, and putting provenance anywhere else
would have made `Level` import the sandbox.

The distinction earns its keep immediately at `reference_benchmark`, which runs
the *level author's* code rather than the player's. For everything in this
repository that is `BUNDLED` and takes the fast path. For a community level it
is a stranger's Python, and that call site is the one that would otherwise have
run it on the host. `run_submission` stays `PLAYER`, because somebody solving a
community level is still typing their own code.

[`tests/test_provenance.py`](../tests/test_provenance.py) is the guard. It
asserts the *absence* of a default, and walks the package's AST for calls to
`run_code`/`run_submission` that do not name their source — which catches the
subtler regression a signature check misses, a caller that passes provenance
positionally or through a wrapper and stops being obvious to a reader. It also
asserts that the checker still finds call sites at all, because a guard that
matches nothing passes for the wrong reason.

## The finding that matters more than the waypoint

**`Source.THIRD_PARTY` covers the code that runs in the sandbox and nothing
else.** A level is an importable module, so loading one executes its body in
the parent; and `make_tests` is a callable invoked *in the parent* on every
`tests_for()`. Both bypass `run_code` entirely. Marking a level `THIRD_PARTY`
does not make either safe.

Nothing can reach that today: the registry walks this package with
`pkgutil.iter_modules` and loads nothing else, so there is no way to introduce
a foreign level at all. But T2's hard gate says *"T5 W6 may not ship unless T2
W1–W3 are landed and verified"*, and as of this session that gate is satisfied
while the danger it was written to prevent is not addressed. Landing W3 is
necessary and, on its own, **not sufficient** — which is recorded in
[T5's hazards](../docs/trajectories/T5-community.md) and pinned by three tests
that fail if the registry ever learns to load from a path, use `exec`, or run
`make_tests` somewhere other than the parent.

Writing that down rather than quietly satisfying the gate is the whole point of
N7. The gate is not wrong; it is incomplete, and the finding belongs in the
record rather than in the exit criteria.

## Misconceptions and corrections

### M12 — Landing W3 satisfies the gate that depends on it

**Believed:** T2's hard gate — "T5 W6 may not ship unless T2 W1–W3 are landed
and verified" — meant that finishing W3 cleared the way for community levels,
which is why the waypoint exists at all.

**Revealed by:** Deciding what provenance `reference_benchmark` should use.
Working out that it runs the *level author's* code led to the question of where
the rest of a level's code runs, and the answer is: in the parent, twice. The
module body runs at import, and `make_tests` runs on every `tests_for()`.

**Corrected to:** W3 secures the execution path. The loading path is a separate
problem that no waypoint currently owns, and community levels need a level
*format* that is data rather than an importable module — or a way to generate
test data inside the sandbox. The gate is necessary and not sufficient.

**Cost:** none in rework; the finding *is* the value. Worth recording that the
temptation was to note it and move on, because the waypoint was complete by its
own words and this belonged to a trajectory two phases away. A gate that can be
satisfied while the hazard it names is still open is worth more attention than
a waypoint that is merely finished.

## Friction

- Making `source` required broke 99 test call sites, which is the cost of the
  guarantee and was paid once. Where provenance is the *subject* of the test
  it is now stated outright; `tests/test_runner.py`, where every case is the
  player's own trivial code exercising sandbox mechanics, states it once in a
  module-level wrapper rather than seventeen times.
- One full-suite run failed a keystroke-latency assertion, then passed three
  times in a row. It was running alongside a Docker pass of the escape gate.
  The latency budget is a real measurement and therefore sensitive to machine
  load; nothing was changed, but a test that fails under load is a test that
  will eventually fail in CI. Recorded as Q27 rather than silently re-run.

## Decisions

| # | Decision | Alternatives considered | Rationale | Reversible? |
| --- | --- | --- | --- | --- |
| D36 | `source` has no default | Default to `PLAYER`; default to `THIRD_PARTY` | Defaulting trusted makes forgetting silent; defaulting untrusted makes forgetting slow *and* changes behaviour under everyone's feet. No default makes forgetting a `TypeError` | yes |
| D37 | `Source` is an enum, not a boolean | `untrusted: bool` | "Untrusted" is a conclusion; the fact underneath is worth keeping, and the policy then lives in one property | yes |
| D38 | `Source` lives in `models.py` | `sandbox.py`; a new `provenance.py` | `Level` must carry one, and `models` depends on nothing — the rule the module map rests on | yes |
| D39 | `reference_benchmark` uses `level.source`, `run_submission` uses `PLAYER` | One provenance per level | They run different people's code: the author's solution and the player's attempt | no |
| D40 | An AST walk guards the call sites | Trust the required argument alone | A signature check misses a caller that passes provenance positionally or through a wrapper | yes |
| D41 | Three tests pin the level registry closed | A comment; nothing | Opening it should be a deliberate act with a failing test attached, not a convenience added on a Tuesday | yes |
