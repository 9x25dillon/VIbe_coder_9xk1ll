## What was built

**Attributes**, on `status`, beside the class. The trajectory is explicit that
this is **no new model** — these are W1's numbers — so the waypoint is
entirely about reading them honestly.

```
── ATTRIBUTES ──────────────────────────────────────────────────
  what you have scored. Your class above is how you write; this is
  a different measurement and the two are never combined.

    algorithms   █████░░░░░░░░░░░░░   27%  5 runs   counts
    recursion    █████████░░░░░░░░░   52%  2 runs   not enough yet   measured 3w ago
    data         ███████████████░░░   81%  7 runs   counts

    aged out of counting: strings  -- play one and it comes back
    9 not measured yet: basics, conditionals, datastructures, …
```

**Three things per row**, because a value alone cannot be read honestly: how
much, on how many runs, and how long ago. The last one matters since W6 — the
number displayed has already had age taken off it, so `52%` means something
different measured on Tuesday than measured in June. `recursion` in that
sheet is stored at 0.55 on five runs and *displays* as 52% on two, which is
decay doing its job where the player can finally see it.

**One renderer, shared with `status --why`.** Two screens describing the same
numbers in two places is two things that can disagree, and the one the player
happens to open is the one they would believe. Same argument as D197.

**Three categories, not two.** A tag whose evidence has decayed away is listed
as *aged out*, never as *not measured yet* — Q91's mistake, on a second
screen. Tags nobody has played are counted, because "what could I be measured
on" is a question a character sheet should answer and a page showing only what
has been rolled cannot.

## Misconceptions and corrections

### M55 — a tag played once vanished overnight

**Believed:** That W6's decay was correct, having been tested at some length
one session earlier — the curve, both directions, purity, every unusable
timestamp. Twelve tests.

**Revealed by:** *Displaying* it. Building the character sheet against a
realistic profile, `tabular` — measured yesterday, one run — was missing from
the rows and listed under *"not measured yet"*. It had been played the day
before.

The cause is one function call. `as_of` computed
`observations=int(self.observations * force)`, and for a single observation
after half a day that is `int(1 × 0.97) = 0`. **Any tag with exactly one run
ceased to exist within twelve hours** and reappeared in the list of things the
player had never done.

Every decay test used six observations, where truncation costs a fraction of a
run and nothing visible happens. The bug lived precisely in the case the tests
did not use, and the case the tests did not use is the *most common one for a
new player* — one run on a tag is where everybody starts.

**Corrected to:** `round`, not `int`. One run now survives to one half-life
and then expires, which is the same schedule everything else follows. W6's
documented table moved by one observation at six weeks; the confidence
behaviour it was chosen for is unchanged, and the table in T4 is corrected
rather than left quoting the old figure.

**Cost:** ~10 minutes.

**Generalisable, and this is the fourth time in T4:** the finding came from
*rendering* the model rather than from testing it. S029's Q88 was a claim I
had propagated without checking; S032's empty-codebase Loopwright came from a
test written while listing failure modes; this came from looking at a screen.
The pattern across all of them is that **the tests were written by whoever
wrote the code, so they inherit its blind spots — and a display is the first
consumer with different ones.** A number nobody looks at is a number nobody
has checked, however many assertions surround it.

Concretely: `int()` on a decayed count is a rounding choice, and I made it
without noticing it was one.

## Friction

The criterion-6 test from W8 broke again, for the second time, because its
slice of the rendered screen swallowed a new section that legitimately varies
with mastery. Both breakages reported a criterion-6 failure that was not one.
The boundary is now an explicit list of what may follow the class block, with
a comment saying why — a test whose scope is "everything after this heading"
will keep being wrong every time the screen grows.

## Decisions

| # | Decision | Alternatives considered | Rationale | Reversible? |
| --- | --- | --- | --- | --- |
| D208 | One row renderer shared by the sheet and `--why` | A renderer per screen, tuned to each | Two descriptions of the same numbers can disagree, and the player believes whichever they opened. Same argument as D197. | Yes |
| D209 | Decayed observation counts round rather than truncate | Keep `int`; floor at 1 while any force remains | M55. Truncation deletes a single observation within half a day, which is where every new player's every tag begins. A floor at 1 would make one run immortal. | Yes |
| D210 | Aged-out tags are a third category, listed separately | Fold them into "not measured yet"; hide them | Telling a player their own history did not happen is Q91's mistake, and it was about to be repeated on a second screen. | Yes |
| D211 | Tags nobody has played are counted on the sheet | Show only measured tags | "What could I be measured on" is a question a character sheet should answer. Listing the names costs one line and makes the map of the game visible. | Yes |
| D212 | The sheet states in words that class and attributes are not combined | Rely on them being separate sections | Exit criterion 8 is about what a screen presents, and saying it is cheaper than hoping the layout implies it. | Yes |
