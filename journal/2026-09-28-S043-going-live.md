## What was built

S042 left T9 W5 open because the server refused connections. The user opened
SSH to this host, and reading the server before touching it changed the plan.

- **The URL moved from `/vibecoder/` to its own origin.** The site's nginx
  config already explains, in writing, why it serves its app on `app.` rather
  than `/app/`: a service worker scoped to `/` owns the whole origin. And its
  `test_edge_headers.py` requires every location in a server block to repeat
  that block's security headers *verbatim* — so a `/vibecoder/` location with
  `'wasm-unsafe-eval'` could only exist by loosening the marketing page's
  policy or carving an exception into the gate. The user chose a subdomain
  (D248), which passes their gate unchanged.
- **astro_caster `4ecf721`** (the site's repository, not this one): a third
  server block with its own verbatim header set and no `/api/` proxy; the
  build bind-mounted read-only from `./vibecoder-web` (gitignored);
  `vibecoder` added to `ops/cloudflare_dns.sh`; a test pinning that the game
  host allows WebAssembly and the landing page still does not. Deployed with
  the site's own `ops/deploy_frontend.sh`, which rebuilt and swapped only the
  frontend container; the backend was not restarted.
- [`tools/web/deploy.py`](../tools/web/deploy.py) rewritten: builds land in
  versioned directories *inside* the target and a relative `current` link is
  renamed over atomically (M66).
- [`tools/web/smoke.py`](../tools/web/smoke.py) gained `--url` (check a running
  site) and `--chrome-arg`, which is how production was tested.
- [`docs/WEB.md`](../docs/WEB.md) hosting section rewritten around an origin of
  its own, with the block as deployed; README points at the live URL.

## Misconceptions and corrections

### M65 — The URL shape was a free choice

**Believed:** `/vibecoder/` on the apex and a subdomain were interchangeable,
so the question asked of the user in S042 was a matter of taste.
**Revealed by:** the site's own nginx config and header test. The config
documents why its app is on a separate origin (a `/`-scoped service worker
owns every path), and the test demands verbatim header sets per server block,
which a WebAssembly-enabled location on the apex cannot satisfy without
loosening the marketing page. **Corrected to:** a subdomain, chosen by the user
with that information. **Cost:** one question re-asked. **Lesson:** read the
host's own invariants before offering a URL shape; the user's first answer was
given before either of us had seen them.

### M66 — Swapping a symlink at a bind mount's path updates the container

**Believed:** S042's `deploy.py` could replace the target path with a new
symlink and the web server would follow it. **Revealed by:** reading the
compose file before the first real deploy: the target is a Docker bind mount,
and Docker resolves a mount's source once, when the container starts.
**Corrected to:** versioned directories inside the mount and a `current` link
inside it, renamed atomically, which nginx resolves per request. **Cost:** a
rewrite of a tool that had not yet been run. **Lesson:** an atomic swap is only
atomic for whoever resolves the name after the swap; find out who that is.

## Friction

- The first firewall change allowed the server's own address rather than the
  build host's, so SSH still timed out until the source address was corrected.
- This host's resolver had cached "not found" for the new name moments before
  it existed; public resolvers answered at once, and the checks pinned the
  Cloudflare address to avoid waiting out the negative cache.
- zsh does not word-split an unquoted variable, so a `curl $R` with two flags in
  `$R` failed until they were written inline.
