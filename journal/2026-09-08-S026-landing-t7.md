### Criterion 8 was false, not merely untested

*"The typing visualiser degrades to a static summary when `animate` is false,
and the game is fully playable with `VIBECODER_NO_ANIM=1`."*

`_draw_pulse` drew the rhythm trail unconditionally, and the trail is a
function of `now` — it scrolls, dims and drains while the player sits still.
The editor's loop ticks every 50 ms specifically to keep it moving. So a
terminal that had explicitly asked for no animation received twenty frames a
second of a draining bar, and composing the same editor state one second apart
produced different output at *both* settings:

```
animate=True    t+0 : ' * ........................~#+~  150 wpm  burst'
                t+3 : ' * ............._+#+...........  150 wpm  thinking'
animate=False   t+0 : ' * ........................~#+~  150 wpm  burst'    <- identical
                t+3 : ' * ............._+#+...........  150 wpm  thinking'
```

`Pulse` now has a `Reading` — wpm, evenness and total, evaluated at the moment
of the **last keystroke** rather than at the current time. It is frozen at
`_last` rather than taking a `now`, so a caller cannot reintroduce the drift it
exists to remove. When `animate` is false the editor draws that instead of the
trail, and the whole frame goes still:

```
animate=False   t+0 : ' *   150 wpm   100% even   11 keys'
                t+3 : ' *   150 wpm   100% even   11 keys'
```

The consequence is the part that matters: an idle editor at `animate=False`
composes a byte-identical frame, `diff` finds nothing changed, and **zero bytes
reach the terminal**. That is what the criterion was protecting — bandwidth on
an ssh link and motion in a log — and it had been protecting nothing.

### Criterion 1 named a path nothing tested

*"Any exit path — normal quit, exception, `SIGINT`, `SIGTERM`, `SIGHUP` —
leaves the terminal in its original mode with the cursor visible."*

`term.py` installs handlers for `SIGTERM` and `SIGHUP` and documents `SIGINT`'s
absence as deliberate: raw mode clears `ISIG`, so Ctrl-C arrives as a key event
rather than a signal. That reasoning is correct, and it is not the whole
criterion — a `SIGINT` delivered from outside the terminal still arrives, and
raises `KeyboardInterrupt`, which is a `BaseException` rather than an
`Exception`. Exactly the sort of thing a stray `except Exception` would skip
the cleanup for. Now tested, along with the premise that `ISIG` really is off.

The criterion also says **"with the cursor visible"**, and the restoration
tests compare `termios` attributes — which say nothing about the cursor, since
it is hidden with a private-mode sequence rather than a terminal flag. Only the
normal-exit path had ever asserted `CURSOR_SHOW`. Six new tests cover it on
every abnormal path, including the two that end with the process being killed
by the signal it re-raised.

## Misconceptions and corrections

### M45 — a trajectory left open is an unchecked claim, not a neutral state

**Believed:** That T7 was finished and only needed closing. The flight board
had said "complete through W8" for five sessions, and **I repeated it in
S025's handoff as "bookkeeping rather than work"** — a phrase written from the
board rather than from the criteria.

**Revealed by:** Reading the nine criteria and testing each one, because
S025's M43 had just cost a session for exactly this shape. Criterion 8 turned
out to be false in the code, not merely untested: the visualiser animated
identically at both settings, which a two-minute script showed and five
sessions of "complete" had not.

**Corrected to:** "Complete through W8" is a statement about *waypoints*.
Waypoints are what gets built; criteria are what makes it done, and nothing
had compared the two. Landing a trajectory is the moment the comparison is
forced — so leaving one open indefinitely does not defer a formality, it
defers the only check the format has.

**Cost:** ~35 minutes, and five sessions of an unmet criterion recorded as met.

**Generalisable:** This is M43 one trajectory later, from the other direction.
There, a criterion was verified by a command the author already knew how to
type. Here, a criterion was verified by nobody at all, and the board's summary
was quoted instead — by me, in the previous session's handoff. **A summary of
evidence is not evidence.** The status line and the criteria drifted apart
precisely because closing the trajectory was postponed, which is the one
action that would have compared them.

### M46 — a degradation test passes on a blank row

**Believed, briefly:** That asserting "the rhythm row is identical at two
different times when `animate` is false" was a sufficient test of criterion 8.

**Revealed by:** Writing it and noticing it would also pass if the row were
empty, absent, or if the pulse were broken and reported nothing at all — every
one of which is a worse product than the bug being fixed.

**Corrected to:** The assertion is paired with
`test_the_rhythm_row_moves_when_animation_is_on`, which fails if the row stops
carrying information. A test that something does not change is only meaningful
next to a test that it can.

**Cost:** ~2 minutes. Recorded because the failure mode is general and quiet:
an assertion of absence passes hardest when the feature is gone.
