## What was built

**[`w2-boss-ledger`](../vibecoder/levels/w2_boss_ledger.py) — "The Ledger".**
Three steps: index the catalogue, total the spend, rank the result.

The shape is the point, and it differs from W1's on purpose. In
`w1-boss-pipeline` only the last step calls anything — the middle step stands
alone, so the "linking" the format exists for is a single edge. Here every link
is real: `totals_by_customer` calls `index_prices`, and `top_spenders` calls
`totals_by_customer`. That is an *assembly* rather than a pipeline, which is
what W8 asked for.

**Step two carries World 2's lesson into a boss.** Its signature takes the
product list, not a price map, so a player can solve it by scanning the
catalogue for every order. That solution is entirely correct and costs 19.5×
the reference's work. It is `w2-l3-join`'s lesson with health bars attached,
and — because the brief *promises* the player this will cost them — it now has
a test rather than being a claim in prose (M36's lesson, Q75's question).

**Everything is integer arithmetic.** Prices are whole cents. A total assembled
in one order by the reference and another by the player has to compare equal,
and floats make that a question about summation order rather than about the
algorithm. The opportunity to need a tolerance was removed rather than managed.

**A baseline that covers bosses.** `data/baselines/2026-09-08-two-bosses-baseline.json`
is the first to record boss step op counts. Since W7 those are load-bearing —
a step's reference op count is the denominator of the Functional axis for a
fight — and nothing was recording them. Two new tests in `test_records.py`
check the coverage and the reproduction, so they are not numbers nobody reads.
The level figures in it are byte-identical to the previous baseline, which is
the evidence that W7 and W8 touched no level.

**T3 landed.** Every waypoint shipped; every exit criterion has evidence.

## Misconceptions and corrections

### M43 — a boss that nobody can find is not "playable from the CLI"

**Believed:** That exit criterion 6 — *a boss fight is fully playable from the
CLI with no web front-end* — had been satisfied since S022, and that W7's
scorecard was the last thing it needed. The flight board said exactly that.

**Revealed by:** Running `vibecoder levels --map` to check the new boss had
appeared on it. **Neither boss appeared.** `cmd_levels` walks `all_levels()`
only, in both the map and the campaign listing, so a boss had never been shown
anywhere in the game. The only way to reach one was to already know its id from
the README or the source.

**Corrected to:** The listings now name every boss and print the command to
start it — `vibecoder boss <id> --live` — because the id is the thing the
player actually lacks. A node on the map they cannot name would not have been
a way in either, which is why bosses get a labelled line rather than a node in
the level row.

**Cost:** ~15 minutes, and two sessions of a criterion being recorded as met
while the feature was unreachable.

**Generalisable:** "Playable" was read as "the code path works", and it was
checked by running the code path — with the id in hand, every time. A criterion
about a *player's* experience cannot be verified by a command the author
already knows how to type. This is the third time in T3 that running the thing
found what the suite could not (S022's unplayable fight, S024's free points on
Functional, and now this), and the pattern in all three is the same: the test
and the author share an assumption, so only the front door disagrees.

### M44 — the first test case is the one the player watches

**Believed, and nearly shipped:** That a starter satisfying "fails some cases,
passes others" was enough. The first draft of step three used `n=2` in its
worked example, and with two customers in that fixture `ranked[:2]` and
`ranked` are the same list — so the starter *passed* the worked example.

**Revealed by:** Reasoning through `_attempt` while designing the case, not by
a test — nothing in the contract checks this. A live step traces `tests[0]`, so
a starter that passes the first case shows the player a clean-looking run and
then a verdict they did not see coming, which is precisely the failure S022 was
about.

**Corrected to:** The worked example uses `n=1`, so the starter returns two
entries where one was asked for, and the wrongness is visible in the value the
player just watched being built. All three steps were then checked to confirm
their worked example is among the failures.

**Cost:** ~5 minutes, caught before it was written down.

**Note:** this is now in `LEVEL_AUTHORING.md` as a rule, but it is **not a
test**, and it could be one — `tests[0]` failing for every starter is a
checkable property. Left undone deliberately rather than silently; it is Q83.

## Friction

Choosing three steps rather than four. Four would make "assembly" more literal,
but the repair pool is five and every starter must fail, so a four-step boss
forces four repairs and leaves one for the whole fight. That is a materially
harsher game than W1's, decided by arithmetic that has never been playtested
(Q76). Three was chosen to keep the two bosses comparable, so that when someone
does play them the difference is the *shape* rather than the budget.

## Decisions

| # | Decision | Alternatives considered | Rationale | Reversible? |
| --- | --- | --- | --- | --- |
| D164 | The second boss is a chain, not a pipeline: every step calls its predecessor | Copy W1's shape, where only the last step links | W1's middle step stands alone, so "linked steps" is one edge. A chain is the stronger reading of what the format is for, and gives the contract tests something real to check at every step. | Yes |
| D165 | Step two takes the product list, not a price map | Pass the index in, as W1's filter step takes parsed rows | Taking the list is what leaves room for the correct-but-quadratic answer, which is World 2's whole lesson. Handing over the index would have removed the trap the world exists to teach. | Yes |
| D166 | Prices are whole cents; the boss is integer arithmetic throughout | Floats with `round(_, 2)`, as `w1-boss-pipeline` uses | A total summed in a different order by the player must still compare equal. Float tolerance is a different lesson than this boss teaches, so the need for it was removed rather than managed. | Yes |
| D167 | Three steps, not four | Four steps for a more literal "assembly" | Five repairs and a mandatory failure per step means four steps leaves one repair for the fight. Harsher than W1 on numbers nobody has playtested (Q76). | Yes |
| D168 | Bosses get a labelled line in the listings, not a node in the level row | A node in the map row; leave discovery to the README | A boss banks no stars, so a node has nothing to put in the label row without inventing a value — and the id is what the player lacks, since `boss` takes one. A line can carry the command; a node cannot. | Yes |
| D169 | The baseline records boss steps, and two tests check it | Leave the baseline level-only | Since W7 a boss step's reference op count is a scoring input. An unrecorded scoring input is a number nothing watches, which is M36's shape. | No — `data/` is immutable (N6) |
