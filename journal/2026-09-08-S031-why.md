## What was built

**`vibecoder status --why`**, in four parts:

1. **What has been measured** — every tag with evidence, weakest first, with
   its run count and whether it is enough to act on. A tag the game has a
   number for and is *ignoring* is shown as such, because hiding it would make
   the drill's choice look arbitrary.
2. **What you would be given right now** — every level, its band, and the
   sentence behind it.
3. **The drill**, if one is warranted.
4. **What this does not know.**

```
  what has been measured   weakest first
    algorithms       ████░░░░░░░░░░░░░░   22%  5 runs         counts
    recursion        █████░░░░░░░░░░░░░   30%  4 runs         counts
    tabular          ██████████░░░░░░░░   54%  1 run          not enough yet
    data             █████████████░░░░░   73%  7 runs         counts

  what you would be given right now
    w2-l3-join       standard  you have played algorithms, data enough for a
                               read: you average 48% there…
    w3-l1-flatten    gentle    you have played algorithms, recursion enough for
                               a read: you average 26% there…

  what this does not know
    - a level's tags all move together, so a score for algorithms, data is
      about the levels that carry it rather than that skill on its own
    - recursion is carried by a single level, so the score measures that
      level as much as the skill
```

**Nothing on the screen is computed for display.** Every sentence is the
`reason` the decision was actually made with — the same object `cmd_play`
acts on. That is what exit criterion 4's "no hidden state" amounts to in
practice, as distinct from a second rendering that happens to agree today and
drifts in November.

### Saying what the model is not claiming

The fourth section is the part the waypoint calls non-negotiable, and it
answers the two questions that had been open since W1 and W5.

`policy.limits` generates the caveats **from the content**, so a level gaining
a tag changes what the player is told without anyone remembering to edit a
paragraph. Both are properties of the model rather than modesty: a level's
tags all receive the same observation (**Q87**), and a tag carried by one
level is measured on one problem shape (**Q88**, stated at the right strength
— thin, not unusable, which is the correction M51 forced).

### Q91: stale is not unknown

A returning player whose evidence had decayed was being told *"nothing
measured yet"* — true of the decayed model and false about their history. The
policy can already tell the two apart without any model change: an aged-out
tag is still present in `Mastery.tags` with its `updated_at`, while a
never-measured one was never there. So there is now a `stale` source:

> you have played data before, but not recently enough for the reading to
> still count, so this is a standard variant while the game takes another look

The decision is the same standard variant either way. Only the sentence is
honest.

## Misconceptions and corrections

### M53 — I padded a painted string, which is invisible in every test I had

**Believed:** That `f"{counts:<20}"` was a normal column pad, where `counts`
was `UI.paint(...)` of a run count.

**Revealed by:** Re-reading the line before running the suite, because T6's
rule — *every element computes its plain-text layout first and paints last* —
was sitting in `ARCHITECTURE.md` two screens above what I was editing. An
escape sequence has no display width but plenty of `len`, so padding a painted
string pads the wrong number and the column drifts the moment colour is on.

**Corrected to:** Pad the plain text, then paint the padded result. Verified
by rendering at `FORCE_COLOR=3`, stripping the escapes, and confirming the
columns land where the piped version puts them.

**Cost:** ~3 minutes.

**Generalisable, and the reason it is worth a numbered entry:** **the whole
test suite would have passed.** Every assertion in `test_cli_output.py` runs
against escape-stripped text or a pipe, where `Depth.NONE` makes `paint` a
no-op and the bug cannot exist. This is a defect whose only symptom is on a
real terminal, in a project whose presentation rule exists precisely because
that class of thing is invisible from CI. T6 landed early for the same reason
and M36 was the same shape. The rule is not "strip escapes when asserting" —
that is already done — it is **compute width before colour**, and following it
is what makes the stripped assertion meaningful in the first place.
