# Work review — 2026-09-10

We took VibeCoder from a set of terminal reports and compact editing screens
to a shared terminal cockpit. The work covered a keyboard campaign browser,
responsive objective and repair inspectors, persistent test feedback, optional
typing rhythm, and a live boss machine with health and repair counts. It reused
the existing cell renderer and added no dependencies. Scoring, persistence
formats, and sandbox rules stayed intact.

The implementation passed 1,420 tests and 54 reference runs. Real PTY smoke
checks exercised browsing, solving, returning to the browser, repairing, and a
live reference fight, including terminal restoration. The rendered preview was
visually inspected. Sustained human playtesting remains open; automated tests
cannot establish whether the density and pacing feel right.

## Two useful vocabulary words

**Invariant:** a condition that must remain true throughout a change.
Example: “Preserve the invariant that piped output contains no escape codes.”
This tells the assistant exactly which existing behavior must survive.

**Granularity:** the level of detail or size of the units of work.
Example: “Use coarse granularity for progress updates, but give precise test
results in the final handoff.” This helps control both scope and communication.

A combined prompt:

> Read the handoff, then implement the agreed terminal overhaul. Preserve the
> invariants around scoring, dependencies, and piped output. Use screen-level
> granularity for progress updates. Verify the 80- and 120-column workflows,
> update the handoff, and deliver through a rebased, tested, merged PR.
